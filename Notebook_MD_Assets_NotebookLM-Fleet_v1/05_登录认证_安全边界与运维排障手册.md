# 05 · 登录认证、安全边界与运维排障手册

## 一、双通道认证体系设计

### 1. Channel 1：官方 OAuth 2.0（永久可刷新令牌）
1. 在 Google Cloud Console 启用 `notebook.googleapis.com`，配置 External 测试受众（Test users 加入全部个人 Gmail），创建 **Desktop app** 客户端。
2. 在 Web 面板「官方 API & MCP 实验室」上传或粘贴 `client_secret.json`（自动识别并回填 `project_id`）。
3. 点击账号卡片或实验室里的「官方 API 授权」，页面通过 `/api/accounts/{id}/oauth-redirect` 生成 30 分钟本地回调监听与 Google 同意页；完成后令牌落盘于 `data/oauth_tokens/<alias>.json`，后续自动调用 `Credentials.refresh()` 续期。

### 2. Channel 2：面向 `notebooklm-py` 的双模式零阻力登录
为了解决 Windows 下日常 Chrome 运行时 Cookie 库文件被锁（`browser database is locked`）及 Playwright 登录易被风控拦截的痛点，系统在 `POST /api/accounts/{id}/capture-cdp`、`POST /api/accounts/{id}/import-cookies-raw` 实现了双通道登录导入：

- **方式一（推荐 · 纯净专属 Chrome + CDP 采集）**：
  - 点击 `🚀 ① 启动专属纯净 Chrome (:9222+)` 启动基于独立 `--user-data-dir` 与 `--remote-debugging-address=127.0.0.1` 的原版普通 Chrome，人工完成 Google 登录（无 Playwright 自动化标记）。
  - 点击 `⚡ ② 一键同步会话并测额`，`browser_takeover.capture_cdp_cookies()` 通过 WebSocket 连接本地 CDP 调用 `Storage.getCookies`（必要时回退 `Network.getAllCookies`）读取全量 Cookie 而不关闭浏览器窗口。
- **方式二（5 秒极速 · Copy as cURL / Cookie / JSON 解析导入）**：
  - 支持直接粘贴日常浏览器开发者工具复制的 `Copy as cURL (bash)` / `Copy as cURL (cmd)`、原始 `Cookie: ...` 请求头、Playwright `storage_state.json` 或 Cookie-Editor 导出的 JSON 数组。
  - `parse_raw_cookie_input()` 自动剥离跨行续行符（`\` / `^`）与 cmd 转义，并精确把 `OSID` 绑定至 `notebooklm.google.com`、将 `LSID` 绑定至 `accounts.google.com`、将其余核心认证 Cookie（`SID`、`__Secure-1PSIDTS` 等）绑定至 `.google.com`。
- **落盘校验**：写入 `storage_state.json` 前强制核验必需主 Cookie（`SID` 与 `__Secure-1PSIDTS`）及二级绑定状态（`OSID` 或 `APISID+SAPISID+LSID`），并通过 `notebooklm.auth.replace_profile_from_login()` 按账号严格隔离写入。

## 二、核心安全防线（绝不妥协的约束）

1. **严格凭据与数据隔离**：
   - `.gitignore` 永久屏蔽 `data/`、`.env`、`*.db`、`*.sqlite`，严禁任何代码/日志存储 Google 明文密码。
   - 多账号严禁共享同一个 Web Cookie Jar，`nlm_profile` 与 `chrome_profile_dir` 全流程按别名隔离。
2. **路径穿越与敏感文件拦截**：
   - `drive_hub.resolve_safe_subpath()`、`workspace.is_allowed_file_for_ingest()` 与 `workspace.is_sensitive_path()` 确保所有浏览、预览、快速导入及主题导入任务只能触及允许的工作区/云盘根路径。
   - `.env`、`client_secret.json`、`storage_state.json`、`master_token.json`、`*.pem`、`*.key`、`*.pfx` 以及 `.git` / `oauth_tokens` / `chrome_profiles` 目录在接口层返回 `HTTP 403`，绝不向前端或笔记本泄漏私密凭据。
3. **只写专属 Hub 目录，不触碰外部存量数据**：
   - 严禁修改工作区外同级历史项目或 `<DRIVE_LIBRARY_ROOT>\` 下 `NLM_Hub` 之外的既有用户文件夹。

## 三、常见运维问题排查清单

| 现象 | 根因定位 | 标准解决办法 |
| :--- | :--- | :--- |
| 官方 API 调用返回 `HTTP 403` | 个人测试期应用未添加 Test user，或使用了 Google Workspace 企业邮箱 | 检查 Google Cloud OAuth Audience 测试用户列表，确保使用个人 Gmail |
| 官方 API 调用返回 `HTTP 404` | 新账号尚未在浏览器初始化过 NotebookLM 网页端 | 使用对应账号访问一次 `https://notebooklm.google.com/` 即可激活 |
| 公网探测报 `ConnectTimeout` | 本地代理/TUN 路由访问 Google `notebook.googleapis.com:443` 握手丢包 | 切换稳定代理节点，或在控制面板「账号台账与策略」填入 `official_proxy_url`（如 `http://127.0.0.1:7890`） |
| 提取本机 Chrome Cookie 报锁定 | 日常 Chrome 正在运行锁住 `Cookies` SQLite 文件 | 无需关闭浏览器，点击「一键登录会话」改用纯净专属 Chrome CDP 采集或直接粘贴 cURL |
| 需要灾难恢复 / 换机迁移 | 需还原账号台账、主题与任务历史 | 从 `<DRIVE_HUB_ROOT>\00_System\backups\fleet_*.db` 复制备份文件覆盖本地 `data\fleet.db` 即可（官方 OAuth 与 `.notebooklm` 目录另行随身迁移） |
