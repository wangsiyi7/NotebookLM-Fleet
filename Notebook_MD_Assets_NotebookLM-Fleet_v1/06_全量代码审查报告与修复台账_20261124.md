## 二、本次全量审查发现并已落地修复的 9 项问题清单

| 编号 | 所在模块 | 原先隐患 | 修复方案 |
| :--- | :--- | :--- | :--- |
| **F1** | `app/main.py` (`lifespan`) | 服务意外重启时，数据库里遗留处于 `status = 'running'` 的任务不会被回收，导致关联账号被调度器持续视为 `busy_ids` 而饿死队列 | 在 `lifespan()` 启动完成建表初始化后，自动将所有残留 `'running'` 状态任务安全重置回 `'pending'` 并清空 `assigned_account_id` 与 `started_at` |
| **F2** | `app/core/scheduler.py` (`select_account_for_task`) | 即便账号已完成 Ch1 官方 OAuth（`official_oauth_status == 'ok'`），只要 Ch2 Cookie 未登录就会被调度器全部拒之门外，无法单独通过官方 API 调度 `ingest_*` 任务 | 增设 `OFFICIAL_SUPPORTED_TASKS`（`ingest_url`/`ingest_text`/`ingest_file`），在全局启用官方 API 且存在 `project_id` 时允许官方已授权账号承接对应导入任务，同时对 Studio 类任务仍严守 Ch2 准入 |
| **F3** | `app/adapters/router.py` (`CapabilityRouter`) | `ingest_file()` 未接入官方通道，`list_notebooks`/`create_notebook`/`ingest_url`/`ingest_text` 也未透传全局 `official_proxy_url`；且官方失败时无差别盲回落 Ch2 会掩盖报错 | 新增 `_proxy_kwargs()` 统一透传代理；`ingest_file()` 对文本/Markdown 自动走 `official.create_source_text`，对其余二进制自动走 `official.upload_source_file`，仅在账号确实已配置 Ch2 时才优雅降级 |
| **F4** | `app/api/inventory.py` | 1）`create_topic(create_remote=True)` 与 `sync_all_notebooks()` 仅筛选 `nlm_auth_status = 'ok'`，忽略纯官方 OAuth 账号；2）`POST /api/topics/{id}/ingest` 接收 `file_paths` 未做工作区敏感路径校验 | 放开官方 OAuth 已授权账号参与建本与全库同步；并在 `ingest_to_topic()` 统一接入 `is_allowed_file_for_ingest()` 拦截 `.env`/`client_secret.json` 等敏感文件与越界路径（返回 `HTTP 403/400`） |
| **F5** | `app/core/quota_poller.py` (`_maybe_run_daily_backup`) | 每日例行备份在异步函数中直接同步调用 `backup_sqlite_to_drive()`，网络盘或云盘同步耗时较长时会短暂阻塞 asyncio 事件循环 | 统一改为 `await asyncio.to_thread(backup_sqlite_to_drive, ...)` 异步线程池执行 |
| **F6** | `app/adapters/official_api.py` & `app/api/official.py` | `upload_source_file()` 直接在事件循环主线程调用 `src.read_bytes()` 且缺少 200 MiB 上限前端前置校验；`/quick-add` 亦存在同步 `stat()`/`read_text()` | 全部磁盘 `stat()`、`read_bytes()`、`read_text()` 均移交 `asyncio.to_thread()`，并在读取字节流前显式拦截大于 `200 MiB` 的超大文件 |
| **F7** | `app/adapters/nlm_py_adapter.py` (`generate_and_download`) | 直接拼接 `topic_name` 作为产物文件名前缀；若主题名包含 Windows 非法字符（如 `:`、`/`、`?`），下载写入时可能触发 `OSError` | 对 `title_prefix` 统一执行 Windows 非法字符正则清洗与长度截断，与 `drive_hub.sanitize_topic_name()` 保持一致 |
| **F8** | `app/adapters/nlm_py_adapter.py` (`check_local_auth`) | 只要 `storage_state.json` 里存在 `SID` 或 `__Secure-1PSID` 任一 Cookie 即判 `ok`，即使缺少 `__Secure-1PSIDTS` 也会放行到 RPC 阶段才报错 | 校验收紧为需同时包含 `SID` 及至少一个 `__Secure-1PSIDTS`/`__Secure-1PSID`，提前识别残缺会话 |
| **F9** | `app/mcp_server.py` (`fleet_open_account_browser`) | Antigravity MCP 工具调用 `mode="official_oauth"` 时仍同步阻塞等待旧版 `run_oauth_flow_for_account`，易引起 MCP 工具调用超时卡死 | 改为与 Web 端一致的异步后台回调监听 + 立即返回 `auth_url` 与永久 `web_redirect_url` |

## 三、刻意保留的架构边界与待接入项

1. **Channel 1 与 Channel 2 的天然职责边界**：由于 Google 2026-11 公测版官方 API/MCP 本身尚未开放额度查询、11 类 Studio 生成、Chat 对话及共享协作者管理，这部分能力按架构预设必须由账号登录 Ch2 后承接；当前主号 `ultra-1` 的 Ch1 已实盘验证可用（50 本在线列表正常拉取），Ch2 会话待用户在面板通过方式一/方式二首次登录后激活。
2. **后台调度定时循环触发前提**：目前 `data/fleet.db` 处于洁净初始生产状态（`ultra-1` 主盘账号已就绪，`topics=0`、`tasks=0`）；若单机未来需扩展多进程部署或跨机器分布式队列，建议再将内存防重与任务认领改为 SQLite 原子 `UPDATE ... RETURNING`（当前单进程 `uvicorn` + 全局 `busy_ids` 完全安全无竞态）。
